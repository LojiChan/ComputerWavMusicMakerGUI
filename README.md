# ComputerWavMusicMakerGUI
CWMmaker & 童祭交响编曲
这是什么
一个把简谱变成 WAV 的小工具，以及用它做出来的一份《童祭 ～ Innocent Treasures》交响改编。

CWMmaker 是我为了给《东方 Project》的曲子做无版权负担的合成演奏而写的一个 Python 程序。它把标准的简谱文本（.txt）直接解析成音频，不需要 MIDI 音源、不需要采样库、不需要 DAW。所有声音都是程序现场合成的。

SheetMusic.txt 里放的是一首《童祭》的完整简谱，五条轨道分别用不同的合成音色演奏，组合成一段约两分钟的交响版本。

它为什么存在
市面上做"简谱转音频"的工具不少，但大多数要么依赖庞大的音源库，要么把谱子转成 MIDI 再由外部软件渲染。这个项目想试一件事：只靠 Python 和 numpy，从零合成一整套乐器音色，并且这个音色在听感上能让普通人认出"这是钢琴""这是小提琴""这是人声"。

结果不好不坏。钢琴、竖琴、吉他这类拨弦乐器效果尚可；管乐和人声距离真实乐器还有距离，但作为"能听出轮廓"的合成版本，够用了。

合成器的做法
音色不是采样、不是波表素材，而是加法合成 + 波表缓存：

每种乐器定义一组谐波幅度和衰减率（参考了乐器声学的公开资料：钢琴的非谐性、小提琴的琴体共振、单簧管的奇次谐波主导、长笛的纯净频谱等）

按每 3 个半音一个精度，把谐波序列预生成成波表

音符按相位累加器查表播放，速度接近实时

在 2 倍采样率下做非线性运算（软削波、噪声、包络），最后用抗混叠滤波器降到 44.1 kHz

这样做的好处是不会有采样库的"机械感"和"音域断层"，坏处是音色精度受限于谐波数量。目前的实现里最复杂的音色用了 24 个谐波，简单音色 5 到 12 个。

《童祭》交响版
《童祭 ～ Innocent Treasures》是 ZUN 为《东方 Project》音乐专辑《夢違科学世紀》写的曲目，是东方圈里非常经典的一首。原曲结构并不复杂：一个 4/4 拍的主歌主题，反复出现并在不同段落里变换速度和配器。

这份改编把原曲整理成一段约两分钟的室内乐合奏：

乐器	角色
少女唱诗班	主旋律
小提琴	对位副旋律
竖琴	琶音背景
钢琴	低音根音
长笛	高音点缀
编制里"少女唱诗班"不是真实人声采样，而是用脉冲串激励 + 共振峰滤波合成的模拟人声。听感上介于人声和电子音之间，可以理解为"合唱音色的近似"。

原曲有好几个 BPM 变化（80 → 90 → 148 → 120 → ... → 46）。在这份改编里，我统一取 76 BPM，因为合奏版本如果跟着原曲的速度变化，不同声部会越走越错位。统一速度后五条轨道才能严格同步。

谱子是用 CWMmaker 的文本格式写的，跟着 SheetMusic.txt 走。每条轨道的音量、声像、八度都写在编曲器的工程里，对应到 OSM 文件夹。

文件

CWMmaker/
├── CWMmakerLauncher.bat    # 双击启动
├── CWMmakerRunner.py       # 主程序（合成器 + GUI）
├── SheetMusic.txt          # 简谱源文件
├── Out/                    # 输出的 WAV

SheetMusic.txt 是纯文本，可以用任何编辑器打开。CWMmaker 的乐谱格式在 README 附带的一份说明里（简谱 + d/g 八度标记 + x 十六分音符 + - 延长 + {} 控制标记），另外还有打击乐记号（K/S/H/O/C）。

已知问题
管乐和人声的合成音色距离真实乐器有差距，人声尤其明显

长曲子的合成需要几十秒到几分钟，视 CPU 核数而定

采样率固定 44.1 kHz，还没做可配置

混响用的是 Schroeder 简化版，空间感偏单薄
